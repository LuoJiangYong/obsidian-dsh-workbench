## 3. 第一性原理与架构约束

### 3.1 用户工作流

用户应能从一个新建任务入口选择知识上下文、项目工作环境和权限后开始任务；首次发送后，任务进入项目或最近，并可在 Obsidian 重启后可靠恢复。运行能力、配置、附件和场景都围绕同一个任务生命周期组合，不再建立三套模式。

### 3.2 不可改变的边界

- DSH 原生 session、完整消息、模型、提供方、Agent、Skill、MCP、工具、权限请求和运行数据继续由 DSH 负责。
- Obsidian Vault 是知识库；插件运行账本、任务索引、项目索引和缓存必须位于 Vault 外。
- 项目源文件夹仍是用户磁盘数据，解除、归档、移除或删除产品记录不得默认删除、移动或修改源文件夹内容。
- DSH 是唯一生产路线。可替换性只通过窄的公开运行时接缝实现，不建立多运行时注册框架，也不实现 PI 或 Codex 适配器。
- Ardot 默认只读；只有用户单独批准 Ardot 修改时才同步设计画板。
- 首版固定 isDesktopOnly: true，不扩展移动端。

### 3.3 最小机制

```text
DSH 原生 session 与公开事件
          ↓ 稳定读取/控制接缝
插件 Vault 外最小任务索引 ── 项目索引与用户排序
          ↓
Obsidian Workbench：新建任务 / 正式任务 / 项目 / 最近 / 运行
```

最小任务索引只保存产品导航和恢复所需的引用与投影，不复制完整对话。最小项目索引只保存显示名称、源文件夹身份、置顶和顺序。任何新增公共抽象仍需至少两个真实消费者和可复现重复痛点。

### R2：Session 读取接缝与最小任务索引

- 唯一结果：插件重启后能从 DSH 公开事实和 Vault 外最小索引重建可继续或明确不可恢复的任务列表，不复制完整对话数据库。
- 为什么现在需要：项目、最近和正式任务导航都依赖稳定任务身份及恢复状态。
- 前置依赖：R1 已确认生产版本和公开 session 能力；DSH 无公开能力时先提出阻塞方案。
- 允许范围：窄的 session 列举/恢复接缝、任务索引 schema、原子写入、损坏隔离和只读投影。
- 禁止范围：项目 UI、统一权限、完整消息复制、私有 DSH 文件解析、跨运行时通用仓库。
- 预计文件：RuntimeAdapter/bridge 的最小公开事件或命令、Vault 外存储模块、类型、测试、ADR、兼容矩阵和 CI。
- 迁移与消费者：为当前生命周期内会话建立显式兼容策略；旧内存会话不得伪造为可恢复。消费者为 N1、D1、U1、L1。

## 8. 项目与导航批次

### D1：项目数据模型与 Vault 外持久化

- 唯一结果：项目名称、一个或多个源文件夹身份、置顶与用户顺序可在 Vault 外原子保存、重启读回，并且不修改源文件夹。
- 为什么现在需要：N1、P1、O1 都需要稳定项目身份，不能把显示名称或路径当唯一主键。
- 前置依赖：R2 的任务引用与存储边界。
- 允许范围：版本化项目 schema、规范路径身份、重复/失效检测、原子持久化和迁移策略。
- 禁止范围：导航 UI、目录删除、DSH 多 cwd 执行、自动扫描文件内容。
- 预计文件：Vault 外存储模块、类型、ADR、测试、设置/路径边界文档和 CI。
- 迁移与消费者：初次为空；未来 schema 必须显式迁移。消费者为项目选择器、导航、排序和权限工作环境。
- 验证：多文件夹、重名、大小写、符号链接/包含关系、失效路径、损坏文件、原子恢复及无 Vault 写入。
- 失败与回滚：损坏数据只读隔离并提示，不覆盖原文件；回滚保留可读备份或旧版本文件。
- 停止边界：只有数据模型，不渲染项目或最近。
- 另行决策：多个源文件夹且未填写名称时，推荐使用首个文件夹名称并要求重名时确认，而不是自动拼接完整路径。

### N1：左侧项目与最近导航

- 唯一结果：Workbench 上方只显示新建任务和运行，下方显示项目与最近；任务只在一个位置出现并能打开同一正式会话。
- 为什么现在需要：先建立可验证的信息架构，再叠加项目编辑和排序交互。
- 前置依赖：R2、D1；最新获批 Ardot 只读核对。
- 允许范围：导航投影、选择态、空态、禁用态、任务打开路由、键盘和无障碍。
- 禁止范围：项目创建/编辑、拖拽排序、归档删除、Ardot 修改和假任务。
- 预计文件：Workbench 视图/样式、任务投影、DESIGN、design-qa、契约/UI 测试和 CI。
- 迁移与消费者：读取 R2/D1，不建立第二份导航状态。消费者为正式会话和后续 P1/O1。
- 验证：项目与最近互斥、最近按活动时间、重启读回、窄屏、明暗主题、键盘、ARIA、隔离 Vault 运行。
- 失败与回滚：无法恢复的任务显示明确状态而非可点击假成功；回滚 UI commit 不删除索引。
- 停止边界：只交付导航，不实现管理操作。
- 另行决策：需要用户验收最终运行 UI；Ardot 是否同步须单独授权。

### P1：项目创建、搜索与编辑

- 唯一结果：用户可从项目区或新建任务选择器创建、搜索、选择和编辑项目，添加/解除源文件夹并在资源管理器打开，所有操作不修改磁盘内容。
- 为什么现在需要：项目必须形成完整的可管理工作流，不能只有不可维护的索引记录。
- 前置依赖：D1、N1。
- 允许范围：原生目录选择、显示名编辑、文件夹增删引用、保存/取消、搜索和资源管理器打开。
- 禁止范围：归档/移除项目、删除文件夹、DSH 多根执行、排序和权限迁移。
- 预计文件：Workbench UI、项目服务、原生菜单、类型、测试、DESIGN、design-qa 和 CI。
- 迁移与消费者：复用 D1 schema；消费者为新建任务、导航、U1 工作环境和 O1 排序。
- 验证：取消、重复文件夹、失效路径、名称冲突、路径变化、保存失败、Windows Explorer 打开和隔离 Vault UI。
- 失败与回滚：编辑采用草稿和原子保存，失败保留旧项目；回滚不触碰源文件夹。
- 停止边界：不实现归档、移除、排序或实际多根运行。
- 另行决策：默认项目名与重名提示必须在实施前确认。

### O1：项目与项目内任务排序

- 唯一结果：项目支持置顶和手动顺序；项目内任务可从活动时间倒序切换为持久手动顺序并显式恢复默认；最近始终按活动时间倒序。
- 为什么现在需要：排序规则已经确认，但必须与任务活动更新和重启恢复共同验证。
- 前置依赖：D1、N1、P1。
- 允许范围：排序状态、置顶分组、移动交互、恢复默认和冲突恢复。
- 禁止范围：最近手动排序、跨设备同步、归档删除、自动按活动重排项目。
- 预计文件：项目/任务索引、导航 UI、菜单或拖拽、测试、DESIGN、design-qa 和 CI。
- 迁移与消费者：旧项目默认进入普通组；旧任务默认 activity 模式。消费者为导航和任务活动更新。
- 验证：重启持久化、新项目插入、置顶组顺序、任务活动不覆盖手动顺序、恢复默认、缺项/重复项修复和键盘替代操作。
- 失败与回滚：冲突时保留所有已知 ID 并确定性追加缺项，不静默丢任务；回滚到 activity 投影不删除保存顺序。
- 停止边界：只交付排序，不进入统一运行或生命周期操作。
- 另行决策：推荐本机单写者、版本号加原子覆盖；多设备合并明确延期。

## 9. 统一运行与权限批次

### U1：统一运行状态迁移

- 唯一结果：新建任务不再要求选择对话/任务执行/代码协作；一个任务状态依据上下文、工作环境和权限组合启动，旧会话仍可只读或按明确兼容规则打开。
- 为什么现在需要：当前状态机和 UI 仍以旧模式分支运行，直接叠加项目会扩大重复状态。
- 前置依赖：R2；项目归属需 D1/P1，非项目任务可独立进入最近。
- 允许范围：状态机、草稿到正式任务转换、旧模式迁移、失败任务保留和单一发送路径。
- 禁止范围：两档权限的最终执行语义、附件、场景、归档删除、DSH 配置复制。
- 预计文件：Workbench state/controller、运行时装配、任务索引、类型、迁移、测试、DESIGN、需求/ADR 和 CI。
- 迁移与消费者：旧模式字段必须版本化读取；不能把旧只读对话静默提升为有工具任务。消费者为 U2、A1、S1、F1。
- 验证：首次发送、启动失败保留、取消、重试、旧记录、项目/最近归属、同 leaf 转换、插件卸载和零残留。
- 失败与回滚：迁移不可判定时保持旧记录只读并提示，不猜权限；保留旧 reader 直到 M1 清理门。
- 停止边界：只统一状态和发送路径，权限仍使用经明确映射的兼容配置。
- 另行决策：旧任务是否允许继续执行，推荐默认只读并允许用户显式创建新任务。

### U2：两档权限与运行中授权

- 唯一结果：标准权限和完全权限按 ADR-011 改变本地文件范围；Shell、网络及已启用能力由 DSH 原生配置提供，越界和高风险请求保持可见、可拒绝、可审计。
- 为什么现在需要：权限不能只换 UI 标签，必须从 DSH 策略、Vault 写入和 MCP 宿主边界证明行为。
- 前置依赖：U1、R1 的权限能力证据以及独立用户决策。
- 允许范围：权限选择、DSH 策略映射、路径 guard、一次性请求、Vault proposal/diff/确认/写入/读回和错误投影。
- 禁止范围：永久全局授权、静默允许、自动修改 DSH 配置、任意未审计 stdio MCP、真实个人 Vault 破坏性测试。
- 预计文件：权限契约、bridge/adapter、路径和 Vault 控制器、UI、ADR、测试、CI 与隔离 Vault 验收。
- 迁移与消费者：旧 chat/task 权限必须显式映射；消费者为所有工具、MCP、附件落地和正式会话。
- 验证：标准/完全路径矩阵、Shell/网络、运行中 allow/deny、删除/批量变更、高风险 Vault 流程、stdio MCP、Windows 隐藏进程和隔离 Vault。
- 失败与回滚：未知策略和无法校验路径一律 fail closed；回滚恢复上一版已验证策略，不扩大权限。
- 停止边界：权限完成后停止，不自动开放附件、场景或管理型 Run 操作。
- 另行决策：阻断。需确认默认档、授权是否仅任务级、Vault 普通/高风险写入门，以及标准权限下 stdio MCP 的宿主边界。推荐标准权限为默认，授权仅当前任务有效，高风险 Vault 操作始终单次确认。

## 10. 组合能力与界面批次

### A1：附件

- 唯一结果：用户能在统一输入区添加经 DSH 当前公开契约支持的附件，并在发送前确认类型、大小、数量、生命周期和数据流向。
- 前置依赖：R1、U1、U2。
- 允许范围：能力探测、选择、预览、移除、发送快照、限额和失败提示。
- 禁止范围：自建附件存储服务、把附件写入 Vault、静默上传或宣称不受支持的类型。
- 预计文件：附件 adapter/UI、临时数据生命周期、设置披露、测试、DESIGN、README 和 CI。
- 迁移与消费者：无旧数据迁移；消费者是统一发送和正式会话。
- 验证：支持/不支持类型、限额、取消、发送时重读、临时文件清理、进程退出、Windows 路径及真实 DSH。
- 失败与回滚：整批失败，不部分发送；回滚删除附件入口与临时材料。
- 停止边界：不扩展项目、权限或健康检查。
- 另行决策：阻断。需依据 DSH 实测确认类型、数量、大小和保存周期。

### S1：知识笔记、日常任务与知识库健康检查

- 唯一结果：旧模式位置改为知识笔记和日常任务场景；首个知识库健康检查使用 Obsidian 原生元数据得出可解释、可取消且默认不写 Vault 的报告。
- 前置依赖：U1、U2；实施时查阅 Obsidian 当前官方 API。
- 允许范围：场景提示/Agent/Skill 组合、胶囊入口、健康指标契约、增量读取、取消和临时报告。
- 禁止范围：独立执行系统、自建索引替代 Obsidian、未经确认写报告、虚构 Wiki 指标或扫描外部项目。
- 预计文件：场景组合、metadataCache/Vault 读取层、UI、指标文档、测试、DESIGN、design-qa 和 CI。
- 迁移与消费者：旧模式标签不成为场景数据；消费者是统一输入和报告视图。
- 验证：结构、孤岛、缺失元数据、未解析链接等获批指标的合成 Vault；大 Vault 性能、取消、缓存失效、零默认写入和隔离 Vault UI。
- 失败与回滚：任何指标不可证明时明确跳过并解释，不输出伪健康分；回滚隐藏场景入口。
- 停止边界：只交付首个场景和指标，不批量建设领域工作台。
- 另行决策：阻断。需确认指标集合、性能上限、报告是否仅临时显示；推荐首版临时报告，写回另行批准。

### F1：正式会话 UI 调整

- 唯一结果：正式会话分离用户消息与 AI 回复，使用缩窄悬浮输入框，只移除页面居中的品牌标题，并保持真实文件卡和 Obsidian 宿主控件。
- 前置依赖：N1、U1、U2；最新获批 Ardot 只读核对。
- 允许范围：正式页布局、输入、状态、错误、文件卡、键盘、窄屏和明暗主题。
- 禁止范围：Ardot 修改、私有推理展示、假历史、归档删除和新的运行能力。
- 预计文件：Workbench 视图与样式、DESIGN、design-qa、UI 测试、截图证据和 CI。
- 迁移与消费者：复用现有正式会话与任务环境；不创建第二套会话组件。
- 验证：真实对话/任务、文件卡三项及展开、停止/错误/恢复、700px 无横向滚动、键盘、ARIA、明暗主题和隔离 Vault。
- 失败与回滚：布局失败不影响原生 session；回滚表现层 commit。
- 停止边界：只调整插件 UI；Ardot 保持只读，用户最终 UI 验收后停止。
- 另行决策：需要用户批准 UI 实施批次，并明确是否另行同步 Ardot。

### V1：运行页 DSH 只读投影

- 唯一结果：运行页只读显示 DSH 公开提供的版本、健康、连接、Agent/预设、模型/提供方、Skill、插件、MCP 和工具事实；不可证明项明确不显示或标为不可读取。
- 前置依赖：R1；可与组合能力在依赖满足后单独批准。
- 允许范围：稳定读取接口、刷新、来源/时间、空态、错误和隐私脱敏。
- 禁止范围：复制 DSH 配置或凭据、启停/安装/更新外部能力、解析私有存储、伪造当前模型。
- 预计文件：RuntimeAdapter 只读能力、运行页、类型、契约、测试、README、DESIGN 和 CI。
- 迁移与消费者：无数据迁移；消费者只有运行页和诊断，不成为执行事实源。
- 验证：字段缺失、版本差异、离线、刷新、脱敏、真实 DSH 与双平台 CI 可执行部分。
- 失败与回滚：读取失败保留健康诊断且不显示陈旧成功；回滚到当前健康页。
- 停止边界：只读投影完成即停止，管理操作需新的能力证据和批准。
- 另行决策：非阻断；推荐首版全部只读。

## 11. 生命周期与最终迁移批次

### L1：归档、移除、删除与恢复

- 唯一结果：项目和任务的归档、移除、删除及恢复具有用户确认的对象范围、DSH session 影响、索引变化和恢复路径，且永不默认删除源文件夹或 Vault 内容。
- 前置依赖：R2、D1、N1、P1；正式语义决策完成。
- 允许范围：已批准的生命周期操作、确认、恢复入口、审计状态和失败恢复。
- 禁止范围：磁盘目录递归删除、模糊“移除”等同删除、无法撤销的批量操作和未公开 DSH 私有删除接口。
- 预计文件：任务/项目控制器、索引、DSH adapter、UI、ADR、测试、DESIGN、README 和 CI。
- 迁移与消费者：必须说明对 DSH session、插件索引、项目归属和运行材料的逐项影响；消费者为导航和正式任务。
- 验证：归档/恢复、移除项目、删除任务、部分失败、重复操作、重启、失效路径、无磁盘内容变化和真实 DSH。
- 失败与回滚：跨事实源操作必须可重试并保留待修复状态；不能证明原子性时拆为可恢复状态机。
- 停止边界：只实现明确批准的生命周期语义，不执行 Release。
- 另行决策：阻断。需确认项目归档、移除后的任务去向，任务归档、删除和恢复语义，以及是否影响 DSH 原生 session。推荐首版只实现可恢复归档和解除本地索引；永久删除另设高风险批次。

### M1：完整迁移、兼容与发布前运行验收

- 唯一结果：旧模式和旧索引迁移到统一任务系统，全部质量门、Windows DSH、专用隔离 Vault 和用户运行 UI 验收通过，形成是否具备另行申请 Release 批次的证据包。
- 前置依赖：所有纳入首个统一工作台里程碑的产品批次完成；未纳入能力必须明确延期。
- 允许范围：迁移清理、兼容矩阵、完整测试、CI、隔离 Vault、用户验收材料和发布准备判断。
- 禁止范围：创建 Release、上传资产、自动更新、社区目录提交、真实 Vault 迁移和新产品功能。
- 预计文件：migration、测试/fixture、兼容矩阵、CI 路线、README、DESIGN、design-qa 和 release verifier。
- 迁移与消费者：覆盖旧 chat/task 记录、旧生命周期内会话、项目/任务 schema 和回滚读者；所有下游消费者必须列明。
- 验证：lint、typecheck、完整 test、build、verify、Windows 进程/正式 DSH、专用隔离 Vault、明暗/窄屏/键盘/错误恢复、精确远端 CI 和原始零 annotations。
- 失败与回滚：任何旧数据丢失、权限扩大、残留进程、Vault 越界或发布检查失败均阻断；保留可回滚 schema reader。
- 停止边界：只形成发布前证据并停止；Release 和 Obsidian 社区提交仍需独立批准。
- 另行决策：需要用户定义首个统一工作台里程碑包含哪些可选批次，并亲自验收最终运行 UI。
