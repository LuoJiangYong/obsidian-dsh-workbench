## 用户结果

每个任务 turn 完成后，中央对话区显示由逐轮账本生成的真实文件卡：默认展示三个文件，超出项可展开或收起；每行显示相对工作区路径、变更类型和确定性文本增删统计。用户可以审核账本中的修改前/后快照，通过 Obsidian 原生右键菜单处理当前文件，并在二次确认后安全撤销整个 turn。

空卡、占位 diff、由模型文本猜测的变更、未归属到当前 turn 的文件和普通 UI 中的完整绝对路径均不允许出现。

## 数据与状态

- 输入：`TaskWorkspaceTurnResult` 中的工作区身份、`turnId`、真实 `changes[]`、增删统计、审核快照与 `canUndo/undone`。
- 显示状态：展开集合、文件操作忙碌状态和可见错误只存在于当前 Workbench 内存，不写入 Vault 或 `data.json`。
- 审核来源：只读取 ADR-007 已完成账本中的 `review.before/after`。二进制或超限文本明确显示“无法内嵌审核”，不回退为重新读取历史内容。
- 当前文件操作：每次执行前重新验证规范工作区身份、路径包含关系、排除目录、普通文件与真实路径；复制当前内容还要求文件不超过 `2 MiB` 且严格为 UTF-8。
- 撤销：控制器只在没有活动 turn 时接受请求，并调用同一 `turnId` 的 `TaskWorkspaceLedger.undoTurn()`。账本完整性、全部当前 SHA 与工作区身份任一不匹配时零写入；成功后以账本返回结果替换当前卡片并禁用再次撤销。

## 原生文件菜单

右键使用 Obsidian `Menu`，提供：

1. 审核本次变更。
2. 使用系统默认应用打开当前文件。
3. 在资源管理器中显示。
4. 复制相对路径。
5. 复制完整路径。
6. 复制当前文件内容。

已删除文件没有当前内容，因此“默认应用打开”和“复制当前文件内容”保持禁用。复制完整路径只发生在用户明确点击后，并进入系统剪贴板；普通页面、消息、日志和账本摘要仍不显示完整路径。

本批不加入“在 VS Code 中打开”：它依赖未验证的外部应用，不是 Obsidian 原生能力。本批也不加入“另存为”：它会新增账本之外的文件写入面，无法由当前 turn 的审核与撤销契约覆盖。“打开方式”不复制桌面应用选择器；系统默认应用是最小且可验证的宿主行为。

## 视觉与可访问性

- 文件卡和菜单触发行不使用方框阴影，沿用现有 Obsidian 主题变量、浅底对话区和一层分隔线。
- 卡片按钮有真实 `button` 语义；文件行主点击打开审核，右键打开原生菜单；展开按钮同步 `aria-expanded`。
- 撤销错误在卡片和确认窗口中以 `role="alert"` 可见，失败后确认窗口保持打开。
- “审核本轮”一次先渲染前 `50` 个文件，其余文件可从展开后的文件行逐项审核；单份内容限制为前 `2,000` 行或 `200,000` 字符。这些限制只约束 UI 投影，不改变账本事实；窄窗口改为单列前后快照。

## 明确不包含

- Vault 写入、删除或移动，任意 Shell、网络、Skill、子代理或完全权限。
- VS Code 专属入口、“另存为”、桌面应用选择器或账本之外的文件复制。
- 正式会话页、跨重启 session 恢复、最近会话导航和右侧环境栏；这些属于 Batch 9。
- Ardot 修改、真实个人 Vault、Release、社区目录提交或 DSH 自动安装/更新。

- 控制器测试覆盖活动 turn 禁止撤销、终态按同一账本撤销、快照替换和重复撤销失败。
