# ADR-003：Ardot 用户审阅 UI 真相与同步协议

状态：已接受
日期：2026-08-24

## 决策背景

`DESIGN.md` 能稳定记录布局和能力边界，但纯文字不足以让用户审阅完整页面、图标、Light/Dark、宽窄响应式和状态组合。代码截图又只代表当时已经实现的结果，不能承担后续产品 UI 目标。需要一个可编辑、可持续演进且与实现能力真相明确分层的视觉权威。

## 决策

1. [Ardot 项目 `DeepSeek Harness Workbench · UI 真相`](https://ardot.tencent.com/file/718186366720195)的最新获用户批准版本，是用户审阅的产品 UI 界面真相。
2. `DESIGN.md` 是 Ardot 审阅真相的稳定文字契约与实现镜像；源码、测试、CI 和运行读回继续负责证明功能是否已经实现。
3. 当前批准基线为页面 `UI 真相 v2`（`12:1`），包括设计系统与交互状态（`12:2`）、新建任务宽屏浅色（`12:41`）、运行宽屏浅色（`12:120`）、新建任务与快速助手（`12:191`）、新建任务宽屏深色（`12:275`）、新建任务 `700px` 容器（`12:360`）和参考截图同屏 QA（`12:530`）。`UI 真相 v1`（`0:1`）只作为历史和失败回退基线保留。
4. 插件身份在 Ardot 中使用 DeepSeek Harness Web 前端的官方鲸鱼矢量，覆盖 Obsidian ribbon、活动标签页、Workbench 左上角和快速助手。该视觉只说明兼容关系，必须继续保留非官方社区集成声明。
5. 未批准草稿、实验画板、静态导出和第三方参考图不能授权代码变更，也不能升级产品能力。
6. 后续 UI 变化必须同步演进：先更新 Ardot 审阅稿并获得批准，再同步 `DESIGN.md`、相关 ADR、实现、测试、CI 契约和 `design-qa.md`；若一个批次明确只更新设计，必须如实登记运行实现差异。
7. v2 把“新建任务”固定为内部导航首位和唯一主对话/任务入口；把“概览”与“运行状态”合并为导航最后的“运行”；右侧快速助手保持可选，不承担主对话。
8. Ardot 产品画板和 Obsidian 插件界面不显示开发阶段、发布批次或治理审批文案；暂不可用导航只使用浅灰文字与图标和真实禁用语义，不添加“规划中”等状态徽标。
9. 首个 Obsidian 社区插件发布功能固定为“新建任务”。只有完整实现、双平台 CI 与隔离 Vault 运行验收通过，并获得用户对最终运行 UI 的明确验收后，才允许进入社区发布审批；该发布门只记录在治理材料中，不进入产品 UI。

## 原因

- 用户可以在一个可编辑项目中审阅完整产品界面，而不必从代码和文字推断视觉结果。
- 视觉真相与能力真相分层，避免把画板、proposal 或空态误报为已经交付的功能。
- 固定文件、版本和画板 ID，使后续变更可以追溯，并让治理测试阻止链接和同步协议无意丢失。
- 同一 Ardot 项目持续演进，避免每批创建新的视觉事实来源。

## 后果与边界

- 当前源码已同步鲸鱼图标、三行品牌、“新建任务”首位、五个浅灰禁用入口和置底“运行”；宿主 UI 与 Ardot v2 不再存在上述结构差异。
- “新建任务”当前只实现宿主页面和确定性状态骨架；上下文、权限、发送和模型连接保持禁用。Batch 5A 隔离 Vault 宿主 UI 运行验收已通过；最终用户 UI 验收仍须在完整功能实现后建立证据。
- CI 通过治理契约验证 Ardot 链接、批准基线和同步要求，不能对远端设计像素做不稳定的网络抓取。
- 视觉验收使用同视口、同状态的参考/实现并排截图；Ardot 设计质量通过不等于 Obsidian 运行验收通过。
- Ardot 变更不自动批准未来模块、聊天、Vault、运行时或发布能力，也不能替代“新建任务”的最终用户 UI 验收。

## 验证

- `tests/contracts.test.ts` 固定 Ardot 文件 URL、v2 页面/画板 ID、导航顺序、产品 UI 文案边界、实现差异、首发门、未批准草稿边界和同步协议。
- `scripts/verify-ci-coverage.mjs` 验证上述契约测试仍由双平台完整 `npm test` 执行。
- `design-qa.md` 保存 v1 历史证据、v2 六个产品画板和参考截图同屏 QA 证据。
