## 1. 阶段结论与用户结果

用户已明确确认第一批开发目标完成。Batch 2–10 的现有实现、测试和运行证据继续由 `new-task-v1.md`、相关 ADR、`DESIGN.md` 和 `design-qa.md` 描述；本文件不重写历史能力真相，也不自动批准 Release 或 Obsidian 社区提交。

下一批产品目标是把当前按“对话 / 任务执行 / 代码协作”分割的入口演进为一个统一运行系统：用户从“新建任务”完成会话前输入，选择知识库、项目工作区和权限后直接发送；会话开始后进入可持续跟进的正式任务，并在左侧下方的“项目”或“最近”中恢复、组织和管理。

## 2. 实施前强制评估顺序

任何代码实施开始前，必须先形成独立、可读回的能力与数据归属评估：

1. 先只读检查 Claudian 当时的公开源码与文档，固定参考版本或 commit，比较其 Obsidian 宿主、项目/会话组织、数据存储、生命周期和文件边界；不把 Claudian 作为 fork 或产品基线。
2. 核实当前获准 DSH 版本的官方契约、公开源码与真实运行能力，优先复用其 session、标题、历史恢复、Agent、模型与提供方配置、Skill、插件、MCP、工具、权限、附件和运行数据能力。
3. 核实当前 Codex 可观察的项目、最近任务、项目编辑、手动排序、置顶、归档和移除行为；截图只用于提出待验证交互，不作为内部存储或删除语义的证据。
4. 查阅当前 Obsidian 官方插件文档与原生 API，确定 ItemView、菜单、文件选择、外部文件夹、状态持久化、键盘和无障碍边界。
5. 输出“原生能力可复用 / 插件必须承担 / 供应商私有 / 尚不可证明”矩阵，再决定最小实现批次。

DSH 仍是唯一生产运行时。实现应以最小运行时接缝隔离 DSH 私有协议，为后续评估 PI、Codex 等同类产品保留演进方向，但本文件不授权建设多运行时框架、实现 PI/Codex 适配器或宣称已经兼容。

“知识笔记”“日常任务”和后续使用场景优先组合 DSH 现成的 Agent、Skill、MCP、工具和提示词能力。只有 DSH 与 Obsidian 都无法完成、且存在明确用户工作流证据时，才建立插件自有功能；不得为每个细分场景建立独立执行系统。

2. `最近`：显示未选择项目的单次任务，按最后活动时间倒序，最新任务在最前。

项目任务与“最近”互斥，不重复展示。点击任务进入同一个正式会话页面继续跟进；`项目` 和 `最近` 不是上方功能页面，也不替代 `运行`。

## 4. 统一“新建任务”与正式任务转换

### 4.1 单一运行系统

- 不再以“对话 / 任务执行 / 代码协作”区分运行能力和权限。
- 输入区始终提供“添加附件”“选择知识库”“选择工作区/项目”“权限控制”四项能力。
- 用户按回车或点击发送后立即开始，不显示统一的执行前确认页；运行中的本地越界授权和独立高风险操作继续遵守各自边界。
- “知识笔记”“日常任务”是使用场景和快捷功能入口，不建立不同运行时或能力清单。选择态左右两端均使用半圆胶囊边界。
- 快捷入口使用 WorkBuddy 风格的可点击胶囊，不把“快捷入口”解释为键盘快捷键。
- 首个二级快捷功能是“知识笔记 / 知识库健康检查”；结构、孤岛、元数据、死链和 Wiki 等具体指标在实施时依据 Obsidian 原生能力与官方文档定义，不在本文件虚构算法。

### 4.2 会话前后边界

- `新建任务` 只承载会话开始前的草稿、项目选择、上下文、工作环境和权限选择。
- 草稿尚未发送时不进入“项目”或“最近”。
- 首次发送后立即建立正式任务并切换到正式会话；即使 DSH 启动失败，也保留可定位的失败任务和用户输入，允许后续重试。
- 选择项目的任务进入该项目；选择“不在项目中工作”的任务进入“最近”。任务归属在首次发送时确定，后续不因活动自动在项目与最近之间移动。
- 会话开始后，用户从“项目”或“最近”的任务项继续对话、查看运行结果和执行后续管理，不再把正式会话挂在“新建任务”选中态下。
- 用户消息与 AI 回复分开呈现；输入框宽度缩小并在正式会话底部悬浮，参考 Codex 的信息关系，不复制其桌面 chrome 或私有数据。
- 只删除 Workbench 页面上方居中的 `DeepSeek Harness Workbench` 可见标题文字；保留标签页名称、鲸鱼图标、标签栏、返回/前进、更多菜单和其他 Obsidian 宿主控件。

## 5. 项目模型

### 5.1 项目身份与创建

- 项目是插件管理的显示与组织记录，关联一个或多个用户明确添加的 Vault 外源文件夹。
- 项目名称默认可取所选文件夹名称，同时支持用户自定义名称；自定义名称不重命名磁盘文件夹。
- 可以从“项目”区域的添加操作创建项目：选择源文件夹并填写或接受默认项目名称。
- “新建任务”的项目选择器必须支持搜索已有项目、选择已有项目、新建项目，以及明确选择“不在项目中工作”。
- 在“新建任务”中完成新项目创建后，该项目自动成为当前任务选择。
- 搜索至少匹配项目显示名称；是否同时匹配源文件夹名称由隐私展示和重名处理评估决定。

多个源文件夹时如何生成未填写的默认项目名尚未决定，实施不得静默采用不可解释的名称。

### 5.2 项目编辑与操作

项目编辑参考用户提供的 Codex 界面，至少规划：

- 修改项目显示名称；
- 显示当前源文件夹；
- 添加源文件夹；
- 从项目中解除源文件夹；
- 保存或取消编辑；
- 归档项目；
- 移除本地项目；
- 在系统资源管理器中打开源文件夹；
- 展开项目并继续其中已有任务。

解除源文件夹、归档项目或移除本地项目都不得删除、移动或修改磁盘文件夹及其中内容。项目归档、移除后的任务去向，以及它们是否影响 DSH 原生 session，必须在实施评估后单独决定。

### 5.3 项目排序与置顶

- 项目不按活动时间自动排序。
- 用户可以手动排序项目，并可以置顶或取消置顶。
- 用户指定的项目顺序必须持久保存；任务活动不得改变项目位置。
- 置顶项目与普通项目的分组、组内手动顺序和新建项目初始位置需在 UI 实施契约中固定，但不得引入自动活动排序。

## 6. 任务排序

### 6.1 项目内部任务

- 默认按最后活动时间倒序，最新活动任务在最前。
- 支持用户手动排序。
- 用户首次执行手动排序后，项目内任务采用持久的用户顺序，后续活动不得自动覆盖。
- 产品需要提供恢复默认“最后活动时间倒序”的明确操作；具体按钮、菜单和拖拽交互在 UI 实施批次确定。

### 6.2 最近任务

- 仅包含没有项目归属的单次任务。
- 固定按最后活动时间倒序。
- 当前不规划手动排序或置顶，避免与项目组织重复；若后续需要必须另行批准。

## 7. 会话、索引与运行数据

- DSH 原生 session、完整历史、模型和提供方设置继续是唯一事实源；插件不复制完整对话数据库。
- 项目、项目显示名称、源文件夹引用、手动顺序、置顶状态、任务归属和最小 DSH session 引用需要在 Vault 外建立可验证的最小索引，禁止写入知识库。
- 如果 DSH 提供公开稳定的 session 标题则优先采用；否则使用首次用户输入的确定性截断标题，并允许用户重命名，不额外调用模型生成标题。
- 项目关联多个源文件夹后，DSH 主 `cwd`、多根文件边界、标准权限范围和工具/MCP 继承方式必须由官方契约与实测决定；不得自行发明不可验证的多工作区执行协议。
- 跨重启恢复、任务列表读回和失败 session 修复必须先证明 DSH 官方恢复能力和插件最小索引的一致性；无法证明时不得显示可继续但实际无法恢复的任务。

## 8. “运行”功能规划

`运行` 保留在上方产品功能导航，继续作为 DSH 公开事实的状态与配置投影中心。未来评估读取：

- 当前运行模式和 Agent 预设；
- 当前模型、提供方与连接状态；
- Skill 的发现、启用状态与配置入口；
- DSH 插件的发现、启用状态与配置入口；
- MCP、工具和其他公开能力；
- DSH 版本、健康状态与兼容性。

只要 DSH 提供稳定读取能力即可先展示；只有 DSH 提供正式、安全、可验证的管理接口时，才评估在 Obsidian 内开放启用、停用或修改。插件不得复制 DSH 配置数据库、凭据、Skill 或插件，也不得自行安装或更新这些外部能力。

## 9. 上下文、工作环境与权限

本文件沿用 ADR-011：

- 当前 Obsidian Vault 是知识库；选中的笔记、选区和文件夹只表达本次上下文。
- 已选择的项目及其源文件夹表达外部工作环境。
- 权限选择器只保留“标准权限”和“完全权限”。
- 两档都默认开放 Shell 与网络，并共享同一套已安装、已启用 Skill、MCP Tools、附件、模型和 Agent 能力；权限只改变本地文件作用范围。
- 标准权限允许当前知识库和已选工作环境，越界本地文件访问在运行中授权；完全权限采用已确认的全磁盘语义。

Vault 高风险变更、stdio MCP 宿主约束、权限默认值和跨会话授权继续由 ADR-011 的未决门控制，不能从统一发送流程推导为已经批准。

## 10. 明确延期的产品语义

以下内容已经识别，但必须在实施时读取 Claudian、DSH、Codex 和 Obsidian 的当前能力后再决定：

- 项目归档、移除与任务归档、删除的准确语义和恢复入口；
- 上述操作是否以及如何影响 DSH 原生 session、插件索引和 Vault 外运行材料；
- 多源文件夹项目的主 `cwd`、多根访问、权限和故障恢复；
- DSH session 列表、跨重启恢复、原生标题、原生归档和删除能力；
- “运行”页面中 Skill、插件、模型和 Agent 从只读投影升级为管理操作的边界；
- 附件类型、大小、数量、生命周期和运行数据存储；
- 知识库健康检查的具体指标、算法、性能边界和报告保存方式。

任何删除或移除行为都不得把项目源文件夹、知识库文件或外部工作成果作为默认删除目标。

## 11. 实施验收目标

未来获批实施必须至少证明：

1. 上方功能导航与下方项目/最近区域层级正确，`运行` 保留且未实现功能不渲染假入口。
2. “新建任务”能搜索、选择、新建或不选择项目；首次发送后准确进入项目或最近并切换正式会话。
3. 项目名称、多个源文件夹、手动顺序和置顶状态在 Vault 外持久化并可读回，不修改源文件夹。
4. 项目内任务默认按最后活动时间倒序，手动排序后保持用户顺序，并可恢复默认排序；最近任务始终按最后活动时间倒序。
5. 项目编辑、在资源管理器打开、解除文件夹和移除项目均进行真实路径校验，且不会删除磁盘内容。
6. DSH 原生能力、插件最小索引和 Obsidian UI 之间只有一个可证明的事实来源，不复制完整 session 或配置数据库。
7. 统一运行、权限、场景、正式会话、错误、键盘、窄屏和明暗主题具有契约测试、双平台 CI 与隔离 Vault 运行证据。
8. Ardot 继续保持只读，除非用户对后续 UI 批次另行明确授权修改。
