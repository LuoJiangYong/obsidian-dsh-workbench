- 状态：Batch 8C–9 已通过完整本地门、双平台 CI 与原始零 annotations；Batch 10 最终运行与用户验收尚未完成

- UI 权威边界：Ardot 文件 `718186366720195`、页面 `UI 真相 v2`（`12:1`）保持 AI 只读且未修改；本文件只记录用户对插件的直接反馈、参考评估和后续实现门

## 1. 结论

插件应吸收 Codex 的“会话导航—中央工作流—可选环境栏”信息关系，但不复制 Codex 的桌面窗口、全局菜单、项目管理器或 Git 专属控件。正式会话开始后，当前“今天想让 DeepSeek Harness 做什么？”开启页应在同一个 Workbench leaf 内切换为正式会话页；右侧信息应使用 Obsidian 原生右侧 leaf，默认关闭且可选打开。DeepSeek Harness 继续作为模型、插件、Agent 预设和完整 session 数据的事实权威，插件只投影当前任务真正启用且安全允许的能力，不再建立一套配置或会话数据库。

## 2. 第一性原理边界

1. 用户要在 Obsidian 内完成任务，而不是在 Obsidian 中运行一个缩小版 Codex 或 DeepSeek Harness Web。
2. Obsidian 的 workspace、leaf、命令面板、设置页、文件菜单和主题变量是宿主边界；插件不复制标题栏、窗口控制、文件树或全局设置外壳。
3. 中央正式会话必须在右侧栏关闭时完整可用；右侧栏只补充环境事实，不能承载必需确认或唯一操作。
4. Vault 默认只读；任务写入只发生在用户当次明确选择、与 Vault 分离的外部工作区。
5. DSH 的完整 session、模型、凭据、插件和预设仍由原生 `$DSH_HOME` 与官方配置管理；插件只保存 Vault 外、最小、可验证的索引或逐轮账本。
6. 不显示私有推理、未验证 token/速度/缓存统计、未启用的工具、虚构会话历史或“完全权限”。

## 4. 正式会话状态机

```text
startup
→ 发送前审阅
→ starting
→ conversation
→ completed | cancelled | failed
```

- `startup`：没有已开始的 session 时显示中央提问、模式、知识库/工作区、权限与输入区。
- 用户输入文本不会提前离开开启页；只有确认发送后才进入 `starting`。
- `starting` 与 `conversation` 使用同一个 Workbench leaf 和同一个控制器，不创建浏览器路由或第二个 Workbench 标签。
- 正式页顶部显示可读会话标题、真实运行状态，以及工作区/权限的简短摘要；不得重复 Obsidian 标签标题。
- 中央区域显示公开用户消息、公开助手文本、工具名称、权限请求、真实文件变更和明确终态；不得显示私有推理或未经证实的指标。
- 底部使用紧凑、可增长的 composer；活动 turn 时主操作变为停止，空闲时可继续同一 session。
- “新建任务”是显式操作：结束或保留当前 session 投影后回到 `startup`，不能通过再次点击 ribbon 意外重置。
- session 恢复必须以 DSH 当前官方契约与真实读回为门；没有恢复证据前，只显示当前插件生命周期内的真实会话，不伪造“最近任务”。

## 5. 三层布局

### 5.1 内部导航

- 保留现有 Workbench 左导航，不复制 Obsidian 文件树。
- 只有真实 session 索引与恢复契约实现后，才加入“最近会话”；没有数据时不渲染空的项目列表。
- `700px` 容器隐藏固定导航，使用现有紧凑页面选择器；正式会话仍不得水平溢出。

### 5.2 中央会话

- 它是完整工作流的唯一必需表面，承载消息、权限请求、执行状态、已编辑文件卡、审核、撤销和 composer。
- 启动页标题与正式会话页头互斥；DOM 中任一时刻只存在一个主标题和一个主 composer。
- 默认已编辑文件展示三项，超出项可展开；审核读取逐轮账本公开投影，撤销必须二次确认。

### 5.3 原生可选右侧环境栏

- 使用 Obsidian `ItemView` 打开在右侧 leaf，默认关闭，显式命令开启并复用同一 leaf。
- 计划展示：已选笔记、外部工作区、当前权限、DSH 运行状态、当前模型/预设摘要，以及本 turn 的变更统计。
- 不放置会阻断任务的唯一确认，不复制主消息流，不默认读取整个 Vault。
- 原“快速助手”已在 Batch 9 原位演进为“任务环境”，沿用既有 view type 与命令 ID，保持默认关闭、同一右侧 leaf 复用和单一视图；没有保留第二个竞争侧栏。

## 6. DSH 能力投影矩阵

| DSH 能力 | 插件首版保留方式 | 数据归属 | 安全门 |
| --- | --- | --- | --- |
| 模型与提供方 | 当前协议未公开 session 模型标识，只显示“由 DSH 配置管理”；未来只有真实读回后才显示具体值 | DSH | 不复制 API key，不维护第二套 provider 数据 |
| Agent 预设 | 当前协议未公开预设标识，只显示 DSH 管理边界 | DSH | 未经兼容验证的预设不进入选择器 |
| 插件、Skill、工具 | 只投影当前 session 实际启用的名称与公开事件 | DSH | 还需通过产品 allowlist、路径 guard、协议与 CI；未启用即不显示 |
| 权限 | 产品级“只读对话”或“仅本次可写外部工作区” | 插件逐请求决定 + DSH session | 不提供完全权限、跨会话永久授权或任意 Shell |
| 完整会话历史 | DSH 原生 session 保存；插件只在官方契约支持后建立最小 Vault 外索引 | DSH | 未验证恢复前不渲染最近任务 |
| 已编辑文件与撤销 | 逐轮公开投影与 Vault 外账本 | 插件 Vault 外状态目录 | SHA 冲突、篡改、过期或边界异常全部 fail closed |
| 推理与性能指标 | 不显示私有推理；指标只有官方公开契约和真实读回后才可显示 | DSH | 不从文本猜测，不把模型输出当运行数据 |

## 8. Batch 9 实现与可验收目标

本地实现使用同一个插件级控制器与 Workbench leaf；首条任务经确认和输入/上下文/工作区校验后建立 session 投影，模式与规范工作区在正式页锁定。关闭/重开 leaf 会恢复当前插件生命周期内的正式页；插件重载后清空，不显示最近历史。显式“新建任务”先处置受管运行时，再清除投影。原右侧视图只显示公开状态、相对笔记标签、工作区名称、逐次权限、已观察工具与账本统计；具体模型/预设因协议未公开而不伪造。详细决策见 [ADR-010](../architecture/ADR-010-formal-conversation-and-task-environment.md)。

1. 确认首条消息后，同一个 Workbench leaf 从开启页切换到正式会话；leaf 总数不增加。
2. 开启页主标题与正式页会话标题互斥，正式页只有一个消息流和一个 composer。
3. 右侧环境栏默认关闭；命令重复开启时复用同一右侧 leaf，关闭后中央会话功能不减少。
4. 精确 `700px` 容器无水平滚动，左导航折叠、右侧栏关闭时仍可发送、停止、审核与继续会话。
5. 键盘可完成模式、上下文/工作区、权限、发送、停止、文件展开、审核、撤销确认和右侧栏开关；焦点可见。
6. 流式与运行状态使用 `aria-live`/`aria-busy`；状态不只靠颜色表达。
7. UI 不显示凭据、完整本机绝对路径、私有推理、假历史或未启用能力。
8. Ardot 记录为“未修改、只读核对”；插件差异同步 `DESIGN.md`、测试、CI 与 `design-qa.md`。
